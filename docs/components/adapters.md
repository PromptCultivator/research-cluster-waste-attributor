# Ingest Adapters

## 1. Overview

The `rcwa.adapters` package translates disparate scheduler accounting formats into the canonical Arrow/Polars data representation. The repository provides two built-in production adapters:
1. `sacct.py`: Ingests Slurm accounting database exports.
2. `swf.py`: Ingests Standard Workload Format (SWF) trace files conforming to the Parallel Workloads Archive standard.

---

## 2. Slurm `sacct` Adapter (`rcwa/adapters/sacct.py`)

### 2.1 Export Command Format

The adapter accepts pipe-delimited output generated by the standard Slurm `sacct` utility:

```bash
sacct -a -P --units=M -S <start> -E <end> \
  --format=JobIDRaw,JobID,User,Account,Partition,QOS,JobName,Submit,Eligible,Start,End,Elapsed,State,ExitCode,\
ReqCPUS,AllocCPUS,ReqMem,MaxRSS,AveRSS,TotalCPU,CPUTimeRAW,ReqTRES,AllocTRES,NodeList,Comment,SubmitLine
```

### 2.2 Parser Implementation Details

- **Header Inspection and Unknown Columns**:
  The parser inspects the header row. Columns outside the 26 canonical fields are ignored, emitting a structured warning without failing execution.

- **Step Hierarchy Rollup**:
  In Slurm, actual consumption metrics are reported on execution steps rather than the parent allocation line:
  - Parent job line (`12345`): Contains user metadata, allocation limits (`ReqCPUS`, `AllocCPUS`, `ReqMem`), partition, and terminal state.
  - Step lines (`12345.batch`, `12345.0`): Contain resident memory (`MaxRSS`, `AveRSS`) and processor execution times (`TotalCPU`).
  - Extern step (`12345.extern`): Contains PAM/cgroup setup metrics. Excluded from CPU usage calculations.
  
  The rollup algorithm groups steps by parent `JobID` and computes:
  $$\text{max\_rss\_mb} = \max_{\text{steps}}(\text{step.MaxRSS})$$
  $$\text{cpu\_time\_used\_s} = \sum_{\text{steps} \setminus \{\text{extern}\}} \text{step.TotalCPU}$$

- **Array and Pack Job Decomposition**:
  - Array tasks (`12345_0`, `12345_1`) and heterogeneous job components (`12345+0`, `12345+1`) represent discrete units of compute.
  - Each task component is ingested as an independent canonical record with `job_id = "12345_0"` and `parent_job_id = "12345"`.

- **Input Hash Extraction**:
  The `Comment` field is scanned for `RCWA_INPUT_HASH=<hex>`. If present, the hex digest is assigned to `input_hash`. If absent, sidecar files in `$RCWA_DIR/<job_id>.json` are checked.

## 3. Standard Workload Format Adapter (`rcwa/adapters/swf.py`)

### 3.1 Format Specification

The Standard Workload Format (SWF) represents supercomputing batch logs as 18 whitespace-separated numerical columns.

| Field Index | Field Name | Description in SWF | Canonical Mapping |
|---|---|---|---|
| 1 | Job Number | Integer identifier | `job_id = str(val)` |
| 2 | Submit Time | Seconds relative to trace start | `submit_time = unix_start + val` |
| 3 | Wait Time | Seconds waiting in queue | `wait_s = max(0, val)` |
| 4 | Run Time | Wallclock execution seconds | `run_s = max(0, val)` |
| 5 | Alloc Procs | Number of allocated processors | `alloc_cpus = val` |
| 6 | Avg CPU Time | Average CPU time used per processor | `cpu_time_used_s = val * alloc_cpus` |
| 7 | Used Memory | KB per processor | `max_rss_mb = (val * alloc_cpus) // 1024` |
| 8 | Req Procs | Requested processors | `req_cpus = val if val > 0 else alloc_cpus` |
| 9 | Req Time | Requested wallclock time | Preserved for backfill horizon calculation |
| 10 | Req Memory | Requested KB per processor | `req_mem_mb = (val * req_cpus) // 1024` |
| 11 | Status | Execution status code | `1 -> COMPLETED`, `0 -> FAILED`, `5 -> CANCELLED` |
| 12 | User ID | Numerical user ID | `user = str(val)` |
| 13 | Group ID | Numerical group ID | `account = str(val)` |
| 14 | Executable No | Executable number | `command_hash = str(val)` |
| 15 | Queue No | Queue number | `partition = str(val)` |
| 16 | Partition No | Partition number | Used if Queue No is missing |
| 17 | Preceding Job | Dependency job index | Preserved for trace provenance |
| 18 | Think Time | Interactive pause time | Preserved for trace provenance |

### 3.2 Header and Metadata Handling

The parser processes header lines prefixed with `;`:
- `; UnixStartTime`: Reference base timestamp added to submit times.
- `; MaxProcs` & `; MaxNodes`: Used to determine physical cluster dimensions.
- `; Note`: Recorded for trace documentation in `docs/DATA.md`.

Missing numerical values in SWF are represented as `-1`. The parser safely translates `-1` in memory and CPU fields to `null` to avoid skewing statistical rightsizing percentiles.

Because SWF traces do not record file system operations, declared inputs are unavailable. Recomputation attribution (Class 4) is reported as `"not available"` on SWF traces and is never fabricated.
